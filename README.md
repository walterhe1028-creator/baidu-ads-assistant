# 百度投放小助手 · GitHub Pages 浏览器版

上传百度报表，说出投放目标，获得逐条操作指导和修改前后对照，下载批量修改清单。

## 新版数字依据与结论

每条建议显示来源报表的消费、点击、展现、CTR、平均点击成本、统计周期与来源行。关键词/搜索词可查看同层级消费占比。现状用暖红背景，建议用蓝色，待确认用琥珀色，均配文字标识。关键词与搜索词核心概览分别统计，不把同一笔流量重复相加；修改步骤含核对位置与后续观察点。

## 使用

1. 打开部署后的网址，首次打开需联网下载报表运行库。
2. 点击「连接模型」，输入自己的 DeepSeek API 密钥，连接后自动读取可用模型。
3. 上传百度原始 CSV 报表，输入目标，点击「告诉我怎么做」。支持关键词、搜索词、创意、单元、方案、项目报表及当前设置快照；UTF-8、GB18030 和 UTF-16 编码。
4. 按卡片逐条核对对象、复制修改内容，或下载 CSV 修改指导清单。分析不会自动修改百度账户；清单不是已验证的百度批量导入模板。

## 只用 GitHub 部署（无需 Render / Supabase）

1. 在 GitHub 新建 **Public** 仓库，建议名称 `baidu-ads-assistant`，勾选添加 README。
2. 将本文件夹内的程序文件上传到仓库根目录，确保 `index.html` 在根目录。
3. 打开仓库 **Settings → Pages**。
4. **Source** 选择 **Deploy from a branch**，**Branch** 选择 `main`、`/ (root)`，点击 **Save**。
5. 等待 GitHub 发布完成。Pages 设置页会显示实际网站网址，通常是 `https://你的用户名.github.io/baidu-ads-assistant/`。

使用 GitHub 免费公共仓库即可，无需买域名或服务器。启用 Pages 及仓库创建取决于你的账号权限。不要把其他旧版文件夹、报表、密钥或 `data/` 上传到仓库。

## 数据和费用

- 网站公开可访问，没有邀请登录。公开的是程序代码，上传的报表不会提交到 GitHub。
- 报表在当前浏览器的 Web Worker 内处理，保存在当前站点的 IndexedDB，报告与结果不跨设备同步。同一电脑、同一浏览器配置的使用者会共享这份本地工作区；个人隔离请使用不同浏览器配置。
- DeepSeek 密钥仅保留在当前页面内存，刷新或关闭页面需重新输入，不写入本地存储、代码、网址或仓库。
- 模型请求从浏览器直接发送至 `https://api.deepseek.com`，发送当前候选、汇总、目标和少量近期对话，可能产生你自己 DeepSeek 账户的 API 费用。网页版不接收客户跟进明细，避免上传客户姓名和电话。
- 清除站点数据、无痕模式、浏览器自动回收空间或更换网址可能导致本机历史丢失。重要清单请下载保存。
- Python 浏览器运行库固定使用 Pyodide 0.27.7，从 jsDelivr 下载。GitHub Pages、jsDelivr 与 DeepSeek 均需当前网络可访问；这不是离线工具。

## 分析与异常

- 每批最多20个规则筛选候选，按钮显示已完整判断的对象比例，等待模型时比例不会自动增长。完成100%表示本轮候选分析完成，不代表全账户所有对象都已检查。
- 单次模型请求超过120秒会明确中断；可以停止分析。页面关闭或刷新会中断模型请求，再打开会提示重新分析。
- 逐条校验候选ID、完整覆盖、重复判断、修改与判断一致性；不合格响应不生成本轮完整修改清单。
- 缺转化不当零转化，留电话不当有效线索；没有当前预算、出价等设置时不会推测修改前值。当前主要业务口径为成都小语种培训，目标描述可补充本轮范围。
- 可通过右上角「清空本机数据」删除本浏览器的报表和分析记录。

## 验证范围

浏览器版复用原版 `engine.py` 和纯数据模型协议，真实报表解析与原版交叉核对。浏览器端模型流程使用模拟响应验证，不代表新产生的实际投放结论。正式使用时仍需连接自己的 DeepSeek API 完成真实分析。

## 文件

`index.html`、`style.css`、`app.js`：页面；`browser-backend.js`：浏览器工作区及模型连接；`report-worker.js`：隔离报表处理；`engine.py`：报表解析及规则；`model_protocol.py`：提示与模型结果校验；`.nojekyll`：关闭 Jekyll 处理。

本目录不含任何真实报表、客户资料、密钥或历史分析记录。
